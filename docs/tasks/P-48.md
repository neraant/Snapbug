# P-48 Refactor: unit tests only for use-cases

Rule (now in `.agents/rules/common/testing.mdc` and `.agents/rules/backend/tdd.mdc`): unit tests exist only for application use-cases, `packages/server/src/modules/*/application/{verb}.test.ts`. Everything else is covered by e2e smoke, types, and lint.

This is a refactoring task: no product behavior and no UI changes.

## Audit scope

Search every `*.test.ts` / `*.test.tsx` in `apps/*` and `packages/*` except `packages/sdk` (the widget SDK keeps its tests; it is a separate runtime and out of scope).

Known non-use-case tests at the time of writing (re-check, the list may have changed):

| File                                                                   | Kind                                                                                          | Expected action                                                                                                                                                                                                     |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/web/src/client/modules/shared/locale/interface-language.test.ts` | util in `apps/web` (not even run by `pnpm test:unit`; uses a `@ts-expect-error` for `vitest`) | delete                                                                                                                                                                                                              |
| `packages/design-system/src/lib/markdown.util.test.ts`                 | util                                                                                          | delete; if it guards sanitization (XSS) behavior that matters, make sure the e2e for tickets/comments renders a comment with a script tag as text, otherwise just delete                                            |

| `packages/server/src/shared/orpc/mcp/*.test.ts` (3 files)              | oRPC wiring                                                                                   | delete, **except** keep a single catalog consistency check only if P-41 requires one in a use-case-shaped test; otherwise replace it with a typed catalog and a TypeScript-level guarantee (exhaustive `satisfies`) |

## Method

1. List all non-use-case unit tests (`rg --files -g '*.test.ts*' apps packages -g '!packages/sdk/**'`) and classify each: delete, or "behavior moves to a use-case".
2. For each test being removed, ask what it protects. If it is a business rule, assert it in the owning use-case test (real entity/mapper, mocked ports) rather than losing it. If it is wiring, formatting, or a util, drop it.
3. Review the existing use-case tests against `tdd.mdc` and trim what it forbids: assertions about mapper fields, SQL, Zod or oRPC, and error-class checks. Keep policy branches, one success with a public dto (no secrets), failure with `errorCode`, and "side effect must not run on failure". Do not reduce policy-branch coverage.
4. Remove now-unused devDependencies and vitest config from `packages/design-system` **only if** `package.json` edits are needed to keep checks green; otherwise leave them and mention it in the PR. Do not touch the `test:unit` script wiring in root `package.json` or `turbo.json` (the implementer rule forbids editing them); if a script becomes empty (`vitest run` with no files fails), keep one use-case-independent passing path by adding `--passWithNoTests` to that package's own `test:unit` script, which lives in the package, not the root.
5. Delete empty folders left behind.

## Done when

- `rg --files -g '*.test.ts*' apps packages -g '!packages/sdk/**'` returns only files under `packages/server/src/modules/*/application/` that sit next to a matching `*.use-case.ts`.
- `pnpm quality` passes.
- The PR description lists each deleted test, the rule it covered, and where (if anywhere) that rule is now asserted.
