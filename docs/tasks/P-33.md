# P-33 Team page: Members and Invitations tabs

Page: `apps/web/src/app/(app)/(admin)/team/page.tsx`, module `client/modules/team` (`team.tsx`, `team-pending-invitations.tsx`, `pending-invitations.tsx`).

## Result

The Team page has a page header (title "Team", description, **Invite people** primary button on the right) and, below it, two tabs:

1. **Members** (default) with a count, e.g. "Members 8"
2. **Invitations** with a count of pending invitations, e.g. "Invitations 3" (count badge hidden at 0)

The "Pending invitations" table is no longer on the Members tab.

## Details

- Add a `Tabs` primitive to `packages/design-system/src/components/ui/tabs.tsx` if it does not exist (underline style, like PostHog/Sentry page tabs; not pills). Keyboard arrow navigation, `role="tablist"`.
- The active tab lives in the URL (`?tab=members|invitations`), survives reload, and is shareable. Invalid value falls back to Members. Switching tabs does not scroll the page and does not reset the other tab's filters.
- Members tab: existing members table and filters, unchanged in behavior.
- Invitations tab: the former pending table moved as is (email, role, projects, invited by, sent, expires, row actions resend / revoke / copy link). Row actions move into a `⋯` dropdown at the row end; revoke goes through `ConfirmDialog` (P-30). Status column shows `Pending` or `Expired` badge (expired in muted/warning tone, with Resend as the main row action). The rework of the invitation logic is P-34, not this task.
- Empty Invitations: "No pending invitations" with an **Invite people** button.
- Invite button is visible on both tabs. After sending an invite from the Members tab show a toast with a "View" action that switches to Invitations.
- Only administrators see this page (unchanged).

## Out of scope

Invitation business logic (P-34).
