# P-35 Project settings sheet: danger zone and layout

Component: `apps/web/src/client/modules/project/components/project-settings-sheet.tsx`.

## Problem

Archive, Restore and Delete sit inside the form area as a block of buttons with a heading, which looks heavy and is easy to hit by accident.

## Result

The sheet becomes a three-part layout:

1. **Header** (fixed): project avatar + name, `Archived` badge only when archived (small, next to the name), close button.
2. **Body** (scrolls): the form sections with consistent spacing — General (name, slug, color, default assignee), Privacy (store visitor IP, collect visitor email, as `SwitchField` rows with label on the left, description under it, switch on the right). Sections separated by `Separator` and a section label, no nested cards.
3. **Footer** (fixed, pinned at the bottom): left side shows the destructive actions, right side shows `Cancel` and `Save changes`. `Save changes` is disabled until the form is dirty. Unsaved-changes prompt when closing a dirty sheet via ConfirmDialog.

### Danger zone

- At the very bottom of the **body** (after Privacy), set apart by extra top margin and a `Separator`, not inside the pinned footer. It is a bordered block with a subtle destructive-tinted border (not a filled red panel), title "Danger zone", muted description.
- Two rows inside, each: label + one-line description on the left, a button on the right.
  - "Archive project" — "New tickets are rejected. Existing tickets stay readable." — `outline` button "Archive" (or "Restore" when archived).
  - "Delete project" — "Permanently removes the project, its tickets and their files." — `destructive` outline button "Delete".
- Both go through `ConfirmDialog` (P-30); delete requires typing the project name.
- Visible to administrators only (members do not see the block).
- When the project is archived: the form fields stay editable except where the server forbids it; the Restore row is the first row in the zone.

## Details

- The sheet width and padding match the other sheets in the app.
- Errors from archive/delete show inside the confirm dialog (P-30), not as a toast only.
- Focus order: fields, Danger zone buttons, footer.

## Out of scope

Server rules for archive/delete. Project card (P-36).
