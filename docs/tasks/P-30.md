# P-30 Confirmation dialogs for actions

## Why

Several actions run on one click (revoke token, remove member, revoke invitation, rotate key, archive). Dialogs that exist today are different from each other (see `project-card.tsx`, `project-settings-sheet.tsx`, `sdk-setup-rotate-api-key-dialog.tsx`). One shared pattern is needed.

## Build

1. A shared `ConfirmDialog` in `packages/design-system/src/components/ui/` (on top of the existing `dialog.tsx`; add `AlertDialog` semantics: no close on outside click while pending, role `alertdialog`). Props: `title`, `description`, `confirmLabel`, `cancelLabel`, `variant` (`default` | `destructive`), `pending`, optional `confirmText` (typed confirmation), `onConfirm`.
2. A small app hook in `apps/web/src/client/modules/shared/` so a call site does not own `open` state boilerplate.

## Layout

- Narrow dialog (about `sm`), left-aligned. Title is a verb phrase naming the object: "Revoke token “CI bot”?", not "Are you sure?".
- Description: one or two sentences, says what happens and whether it can be undone ("Anyone using this token loses access immediately. This cannot be undone.").
- Footer: `Cancel` (outline) on the left of the primary button; primary on the right. Destructive variant paints the primary button red and uses the specific verb ("Revoke", "Remove", "Delete"), never "OK"/"Yes".
- Pending: the primary button shows a spinner and both buttons are disabled; the dialog stays open until the request finishes. On error the dialog stays open and shows the error inline above the footer.
- Initial focus is on `Cancel` for destructive dialogs, on the primary for non-destructive. Enter confirms only when focus is on the primary.
- Typed confirmation (irreversible, high impact: delete project): an input under the description, "Type **project-name** to confirm"; the primary stays disabled until it matches exactly.

## Where it applies

| Action                           | Variant           | Typed                                          |
| -------------------------------- | ----------------- | ---------------------------------------------- |
| Revoke MCP user token            | destructive       | no                                             |
| Remove team member               | destructive       | no                                             |
| Change member role to/from admin | default           | no                                             |
| Revoke invitation                | destructive       | no                                             |
| Resend invitation                | none (toast only) | —                                              |
| Rotate project API key           | destructive       | no (keep existing copy about old key stopping) |
| Archive project                  | default           | no                                             |
| Restore project                  | none              | —                                              |
| Delete project                   | destructive       | yes, project name                              |
| Delete own comment               | destructive       | no                                             |
| Leave / switch organization      | none              | —                                              |

Do not add a confirm to harmless or easily reversible actions (copy, filter, status/assignee change, edit save, restore, resend).

Migrate the existing ad-hoc confirm dialogs to `ConfirmDialog` and delete the duplicated markup.

## Out of scope

Secret reveal dialog (P-31). Layout of the places that host the trigger buttons (later tasks).
