# P-38 Ticket comments, Jira-style

Files: `client/modules/ticket-detail/components/ticket-detail-comment-section.tsx`, `ticket-detail-comment-list.tsx`, `ticket-detail-comment-thread.tsx`, `ticket-detail-comment-thread-item.tsx`. Page `apps/web/src/app/(app)/tickets/[shortId]/page.tsx`.

## Problem

The block looks raw. Edit and Delete are plain text words. Reference: Jira issue "Activity → Comments".

## Result

Section header: "Comments" with the count, optionally a sort toggle "Newest first / Oldest first" (default oldest first, like a conversation; the composer is at the bottom).

### Comment item

- Row layout: avatar (32 px) on the left; on the right a header line **Author name** (medium weight) · relative time ("2 hours ago", full timestamp in `Tooltip`) · "edited" muted label if edited; below it the body rendered with the existing `Markdown` component (links, code, lists). No card border around each comment; comments are separated by spacing only, like Jira.
- Actions only for the author's own comments: appear at the right end of the header line on hover/focus (always visible on touch) as **icon buttons** with tooltips: pencil (Edit), trash (Delete). Or a single `⋯` dropdown (Edit, Delete) — choose one pattern and use it consistently. Others' comments show no actions. No text links "Edit"/"Delete".
- Delete → `ConfirmDialog` (P-30). Deleted comment is removed with a short fade; focus moves to the composer.
- Edit → the body switches to the same editor in place with `Save` and `Cancel` buttons below (Esc cancels, Cmd/Ctrl+Enter saves). Save is disabled while empty or unchanged.
- Long comments (over ~8 lines) collapse with "Show more".

### Composer

- At the bottom, the current user's avatar on the left and a single-line-looking textarea that expands on focus (min 3 lines when focused). Placeholder "Add a comment…".
- When collapsed (not focused, empty) there are no buttons. When focused or non-empty: `Comment` primary button and `Cancel` ghost button appear under it, with a muted "Markdown supported · Cmd+Enter to send" hint on the right.
- Submit shows pending state, then the new comment appears in place and the composer resets; scroll the new comment into view.
- MCP/agent-authored comments (`add_comment`) show a small `Badge` "Agent" next to the name if the author is a token/agent, otherwise render as normal.

### States

Loading: 2 comment skeletons. Empty: "No comments yet. Start the conversation." directly above the composer, no big illustration. Error on send: inline message under the composer, text preserved.

## Out of scope

Mentions, reactions, attachments, comment threading.
