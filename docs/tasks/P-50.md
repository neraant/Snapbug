## B. Comment item layout: two columns

### Today

`ticket-detail-comment-thread-item.tsx` renders a `Row` containing an avatar, a header row, and the body as siblings in one wrapping row, so the avatar and the content do not form clean columns.

### Target

Exactly two columns in a CSS grid or a non-wrapping flex row:

- **Column 1 (fixed width):** the avatar only, aligned to the **start** (top-left, `items-start`, `shrink-0`, does not stretch with the content height).
- **Column 2 (`min-w-0 flex-1`, a `Column`):** header (author, agent badge, "·", relative time with exact-time tooltip, "edited"), the hover/focus action icons on the right of the header, then the body or the inline edit form (textarea + Cancel/Save).

Rules:

- Edit mode keeps the avatar in column 1; the form lives in column 2 only.
- Long author names truncate; long unbroken words in the body wrap (`min-w-0`, `break-words`).
- The same two-column structure for `ticket-detail-comment-composer.tsx`: avatar of the current user in column 1, input and the Save/Cancel buttons in column 2, so composer and thread share the same left edge and text edge.
- Remove the removing/opacity behavior only if it breaks; otherwise keep (it is the delete animation).
- Both themes, 768 px and 1280 px checked. No new strings.

## C. MCP token creation dialog

Files: `apps/web/src/client/modules/user-token/` (`create-user-token-dialog.tsx`, `create-user-token-permissions.tsx`, `hooks/use-create-user-token-dialog.ts`, `utils/count-token-tools.util.ts`, `consts/texts.const.ts`), `packages/validation/src/modules/user-token/consts/mcp-scope.const.ts` and `mcp-scope-meta.const.ts`, `apps/web/src/client/modules/shared/components/secret-reveal-dialog.tsx`.

### C1. "This token can use 13 of 14 tools" with Full access

Cause (confirmed in code): `countTokenTools` always skips tools in `MCP_ADMIN_ONLY_TOOL_NAMES` (`list_activity`), so the count can never reach the total of 14 even though the Full access preset includes `activity:read`. The number looks like a bug.

Fix: the summary must tell the truth about the signed-in user.

- Compute `total` as the number of tools **available to this user** (all 14 for an organization admin, 13 for a member), and `allowed` as before. Admin status comes from `useFindMembershipByUser`. Result: an admin with Full access sees "14 of 14", a member sees "13 of 13".
- For a member, the Custom list hides the Activity group entirely, and the Full access preset for a member does not include `activity:read` (so a stored token never claims a scope its owner cannot use). Server side already requires both scope and owner right; keep that.
- Remove the "only counts non-admin tools" hack from the util; keep the util free of UI texts.
- No unit test (util, per testing rule). The existing e2e for the token dialog asserts the summary text; update it to the new numbers.

### C2. "Token created" dialog: remove "How to use"

`SecretRevealDialog` is shared (new MCP token and rotated project key). For the token flow:

- Remove the usage snippet / "How to use" section. Connection instructions already live on the MCP page, tab Connect (P-42).
- Keep: title, one-time warning, masked secret with reveal and copy, "Done".
- Add one muted line with a link: "How to connect → MCP · Connect" that goes to the Connect tab (`url.mcp()` + tab param) and closes the dialog.
- For the rotated project key keep the snippet only if it is useful there (widget install snippet); otherwise remove the snippet slot from the dialog's props. Do not leave an unused prop.
- Texts EN+RU; remove the now unused usage texts.
