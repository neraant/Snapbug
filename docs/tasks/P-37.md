# P-37 Settings page: tabs and one consistent layout

Page: `apps/web/src/app/(app)/settings/page.tsx`; modules `client/modules/organization` (`organization-settings-form.tsx`), `client/modules/user` (`interface-language-form.tsx`), `client/modules/user-token`, and MCP page `apps/web/src/app/(app)/mcp/page.tsx` for tokens if it is a separate page now.

## Problem

Cards on this page have different paddings, headings and widths. It looks unfinished, everything is stacked on one long page.

## Result

Pattern from PostHog / Sentry settings: page header, a tab bar, and one section per tab. **No stacked cards of mixed shapes**; every section uses the same "settings section" layout.

### Page header

Title "Settings" and a muted description. Tab bar directly below (underline `Tabs` from P-33), tab in URL (`?tab=`).

### Tabs

| Tab | Content | Visible to |
| --- | --- | --- |
| Profile (or Account) | Interface language (English / Russian segmented control, saves on change, one title + description) | everyone |
| Organization | Organization name, data retention period (select), `Save` | admin edits; member sees read-only values |
| Access tokens | MCP user tokens: list + **Create token** (P-31 dialog, P-30 revoke confirm) | everyone |

Add no new settings. Organization-level future items (2FA, GDPR, delete workspace) are TBD and not shown.

### Settings section layout (the one shared pattern)

Create a small shared layout component, e.g. `SettingsSection`, in the design system `components/layout/`:

- Two-column row at ≥1024 px: left column (about 1/3) with section title and muted description; right column (about 2/3) with the controls. Stacks into one column below that.
- Rows are separated by a `Separator`, same vertical padding for every row, same container max width for every tab (about 960 px), same left alignment as the page header.
- Form footer inside the right column: `Save` button aligned left under the fields, disabled until dirty, with inline "Saved" confirmation. Language has no Save (saves on change; show a quiet "Saved" check).
- No `Card` borders around sections.

### Tokens list (Access tokens tab)

A `Table`: Name, Created, Last used (if available, else omit), actions `⋯`/Revoke button. Empty state with the Create token button. Revoke asks `ConfirmDialog`.

## Details

- Loading skeletons per tab. Read-only organization form for members has a muted note "Only admins can change these settings."
- Dirty form + tab switch: no data loss prompt needed because each tab form is independent; but unsaved changes show a prompt via `ConfirmDialog` when leaving the tab.
