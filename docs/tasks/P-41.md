# P-41 MCP tool catalog: which endpoints become tools

Where tools are declared: a contract opts in with `.meta({ mcp: true, name: "…" })` (see `packages/server/src/modules/bug-report/bug-report.contract.ts`, `comment.contract.ts`); the walker is `packages/server/src/shared/orpc/mcp/walk-mcp-tools.ts`; the handler is `create-mcp-handler.ts`, served at `apps/web/src/app/api/mcp/route.ts`.

## Problem

Only `list_tickets`, `get_ticket`, `get_screenshot`, `update_ticket`, `add_comment` are exposed. An agent working on bugs needs a fuller, deliberate set. `docs/SPEC.md` AC-30 ("only these") is replaced by this catalog; this task updates AC-30 accordingly.

## What the agent must do

1. Walk every contract in `packages/server/src/modules/*/*.contract.ts`.
2. Write the decision table as `docs/decisions/` is protected, so put it in this task's PR description and in code as a single typed catalog file `packages/server/src/shared/orpc/mcp/mcp-tool-catalog.const.ts` (name, module, description, access `read|write`, scope from P-43, `reason`). The catalog is the source of truth for the UI (P-42) and scopes (P-43).
3. Opt in the chosen contracts with `meta({ mcp: true, name, readOnlyHint, destructiveHint })`. Every tool has a clear imperative description written for an LLM (what it does, when to use it, what it returns) and every input field has a `describe()`.

## Selection criteria

Include an endpoint when **all** hold: useful to a person or agent fixing bugs; works for the token owner inside the projects they can access; cannot escalate privileges; output is bounded (paginated, no secrets, no replay blobs).

Expected **include** (agent verifies against code, may adjust with a reason):

| Group           | Tools                                                                                                                                                                                        |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tickets (read)  | `list_tickets` (filters: project, status, severity, assignee, text, cursor), `get_ticket`, `get_screenshot`, `list_ticket_logs` (console/network summary, bounded), `get_ticket_environment` |
| Tickets (write) | `update_ticket` (status, severity, assignee), `add_comment`, `list_comments`                                                                                                                 |
| Projects (read) | `list_projects` (only accessible, with ids and slugs), `get_project`                                                                                                                         |
| Members (read)  | `list_members` (id, name, role; no emails unless admin) so an agent can assign                                                                                                               |
| Overview (read) | `get_overview_stats` (counts by status/severity, for a project)                                                                                                                              |
| Search          | `search` (same scope as global search)                                                                                                                                                       |
| Activity (read) | `list_activity` (admin only; own projects)                                                                                                                                                   |

Expected **exclude** (with the reason recorded): anything about tokens, API key rotation or reading keys, invitations, membership/role changes, organization settings and retention, project create/archive/delete, user/auth/password endpoints, replay (stays excluded by SPEC), delete comment, ingest endpoints, audit writes. Destructive or privilege-changing actions stay in the web UI.

## Behavior requirements

- Rights equal the token owner's (admin-only tools return "not found/forbidden" for members; hidden from `tools/list` for members when cheap).
- Cursor pagination with `nextCursor`, limit max 50, default 20.
- Every write is audited with source `mcp` (existing rule).
- Errors are returned as MCP tool errors with a short actionable message, never stack traces.
- Unit tests: catalog consistency test (every `mcp: true` contract is in the catalog and vice versa; every tool has description and described inputs; no excluded module is exposed), plus a happy-path and a forbidden-path test per new tool.

## Out of scope

UI (P-42), scopes (P-43).
