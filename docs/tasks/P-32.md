# P-32 Activity log: infinite scroll, minimal table, detail sidebar

Replaces P-27's table (not its recorded facts). Page: `apps/web/src/app/(app)/(admin)/activity/page.tsx`, module `client/modules/activity-log`.

## 1. Infinite scroll

- Load the first page (50 rows). When the user scrolls near the end (sentinel with `IntersectionObserver`, about one screen early), load the next page with cursor pagination. No "Load more" buttons and no page numbers.
- Server: the activity-log query takes `cursor` + `limit` and returns `{ items, nextCursor }`. Order is newest first with a stable tie-break. Use `useInfiniteQuery`.
- While the next page loads show 3 skeleton rows at the end of the table. At the end of data show a muted line "You've reached the beginning" (no spinner).
- A failed next page shows an inline "Couldn't load more · Retry" row; already loaded rows stay.
- Scroll position is kept when the sidebar opens or filters are unchanged. Header row is sticky inside the scroll container.
- New events are not injected live; a refresh happens on filter change or window refocus only.

## 2. Table: minimum information

Columns (nothing else):

| Column | Content |
| --- | --- |
| When | relative time ("3 min ago"), full timestamp in a `Tooltip`; fixed width |
| Actor | small `Avatar` + name (muted "System" for non-user) |
| Event | one human sentence: **verb + object**, e.g. "Changed status of **#SB-42** to Fixed", "Revoked invitation for **a@b.com**". Object name is medium weight, truncates with ellipsis. |
| Object | `Badge` with the object type (Ticket, Project, Member, Invitation, Token, Organization) |

- Row height is compact and uniform (single line). No JSON, no before/after values in the row.
- Row hover highlights; cursor pointer; a trailing chevron appears on hover. Whole row is a button (Enter/Space opens).
- Group by day with a sticky muted date divider ("Today", "Yesterday", "12 Nov 2026"). Optional but preferred.

## 3. Filters (above the table, single toolbar row)

- Search input (event text/object name), `Actor` select, `Object type` select, date range select (Last 24 h / 7 days / 30 days / All). Active filters show a "Clear" ghost button. Filters are in the URL query string.
- Empty result with filters: "No events match these filters" + Clear. Empty without filters: first-run empty state.

## 4. Detail sidebar

Clicking a row opens a right `Sheet` (same component and widths as the team member edit sheet and project settings sheet). Row stays highlighted while open; the URL gets `?event=<id>` so the link is shareable and reload keeps it open.

Sheet content:

- Header: object-type badge, event sentence as title, close button. Prev/next arrows (and `↑`/`↓` or `j`/`k`) move through loaded rows without closing.
- "Summary" list (label/value rows, same style as ticket property rows): Actor (avatar, name, email), When (absolute time with timezone + relative), Object (name; link to the ticket/project/member page when it still exists), Action, Event ID with copy button.
- "Changes" section: a diff table `Field | Before | After` with removed value muted and struck through and new value normal weight. Long text values wrap. If nothing structured is recorded, show the raw details in a `Code` block.
- Footer: none.

## Out of scope

Changing which facts are recorded. Export. Live streaming.
