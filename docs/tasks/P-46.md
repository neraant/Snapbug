# P-46 Notifications: bell, popover, inbox page (part 2 of 3)

Depends on P-45 API. Module `apps/web/src/client/modules/notification/`; header slot next to global search and the user menu (`app-sidebar-header.tsx` / app layout header); page `apps/web/src/app/(app)/notifications/page.tsx`.

## Bell button

- Icon button (`BellIcon`) with `aria-label`, `Tooltip` "Notifications". Fixed size; the header never shifts.
- Unread badge: small filled dot with number (1–9, "9+"), top-right of the icon, absolutely positioned (no layout shift). Hidden at 0. Count from `unreadCount`, refetched every 60 s and on window focus.

## Popover (click the bell)

Anchored right-aligned popover, about 400 px wide, fixed max height 480 px with inner scroll. Pattern: GitHub/Linear/Sentry.

- Header: "Notifications", tabs **Unread** | **All** (small segmented), right side `Mark all as read` ghost button (disabled at 0) and a settings icon linking to Settings → Notifications (P-47).
- Items (infinite scroll inside, same loader pattern as P-32):
  - Left: actor `Avatar` (or system icon for system events) with a small type icon overlay.
  - Middle: one-sentence text with bold object ("**Anna** assigned you **SB-42** Checkout fails on Safari"), second line muted: project name · relative time. Grouped items read "**3 new comments** on SB-42".
  - Right: unread blue dot; on hover a ghost icon button "Mark as read"/"Archive".
  - Whole item is a link to the object (ticket, project, team page, SDK page) and marks it read on click.
- Unread items have a subtle background tint; read items are plain. Day dividers ("Today", "Earlier").
- Empty: `Mascot` or icon, "You're all caught up" (Unread tab) / "No notifications yet" (All).
- Loading: 4 skeleton rows. Error: message + Retry.
- Footer: link "View all notifications".
- Keyboard: Esc closes, ↑/↓ moves through items, Enter opens.

## Inbox page

`/notifications`: page header "Notifications" with the same tabs, plus a type filter select (All, Tickets, Comments, Team, Security) and `Mark all as read`. Same item component in a full-width list, with infinite scroll. Row actions: mark read/unread, archive. Selecting several (checkbox on hover) shows a bulk bar "Mark read · Archive".

## Behavior

- Opening the popover does not mark items read by itself; clicking an item or "Mark all as read" does.
- Optimistic updates for read/archive with rollback on error; badge updates immediately.
- A notification whose object is gone or inaccessible shows muted "This item is no longer available" and is not a link.
- Toast on new notifications is **not** shown in v1 (avoid noise); the badge is enough.
- EN + RU strings per type, built from `payload` (no stored text).

## Tests

One e2e spec: seed a notification, bell shows the count, open popover, click item navigates and the count drops, "Mark all as read" clears the badge.

## Out of scope

Realtime push, sound, browser/OS notifications, email (P-47).
