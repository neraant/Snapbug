# P-51 Navigation order, one table style, notification item

Three UI consistency fixes. Order: A (small), B (shared table), C (uses nothing from B but is the same kind of work).

## A. Sidebar order

Files: `apps/web/src/client/modules/shared/ui/app-sidebar/consts/app-sidebar.const.ts` (two arrays today: `appSidebarItems`, `appSidebarAdminItems`), `components/app-sidebar.tsx` (concats them: admin links land **after** Settings, which is why the order looks random), `consts/texts.const.ts`, `packages/design-system/src/components/layout/sidebar.tsx`.

Target order, top to bottom:

**Work** (everyone): Overview, Tickets, Playground
**Setup**: Projects (admin), SDK (the "SDK setup" page), MCP
**Organization**: Team (admin), Activity (admin)
**Footer** (pinned, not a nav group): Settings stays reachable from the user menu **and** as the last link of the nav.

Rules:

- The SidebarLayout in the design system gets **groups**: `groups: { label?: string; items: SidebarItem[] }[]` (keep `items` working or migrate every caller). Group label is a small muted `SidebarGroupLabel`, hidden when the sidebar is collapsed to icons (a thin separator instead). Non-admins simply have fewer items; a group with no visible item is not rendered.
- Replace the two arrays by one array of groups with an `adminOnly` flag per item; `app-sidebar.tsx` filters by `isAdmin` instead of concatenating.
- Group labels EN+RU in `texts.const.ts`.
- Active-link logic, project scope search param handling (`buildPathWithProjectScopeSearchParam`) and tooltips in collapsed mode are unchanged.
- e2e: assert the order of links by accessible name for an admin and for a member.

## B. One table style (Sentry/PostHog density)

Tables today use `<Table` in: `activity-log/components/activity-log.tsx` and `activity-log-row.tsx`, `team/components/team.tsx`, `team/components/pending-invitations.tsx`, `user-token/components/user-token-list.tsx`, `notification/components/notification-settings-form.tsx`, plus `mcp-tool-detail-sheet.tsx`. The MCP tools tab uses cards and the notification inbox uses a list. They differ in header, row height, padding, borders, hover, empty and loading states.

Do:

1. Audit each table against the checklist below and write the differences in the PR description.
2. Fix the **one** base in `packages/design-system/src/components/ui/table.tsx` so that the default look is the target (no per-module class overrides for spacing, borders, or typography). Add small composable parts if needed, in the same style as the other ui components:
   - `Table.Toolbar`-like slot (search/filters left, actions right) with the same height and gap everywhere;
   - `TableEmpty`, `TableLoading` (Skeleton rows with the same row height, no layout jump), `TableError` (message + Retry button) used by every table.
3. Migrate all the tables above to it. Delete leftover local wrappers.

Checklist (target):

| Aspect         | Value                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Container      | one bordered rounded container, no card inside a card, full width of its section                                         |
| Header row     | muted, `text-xs`, medium weight, uppercase off, sticky top when the table scrolls, bottom border                         |
| Row            | one height token (compact), `px`/`py` from the spacing scale, 1px divider between rows, no zebra                         |
| Hover/focus    | `bg-muted/50` on hover, visible focus ring; clickable rows are focusable and open on Enter                               |
| Cells          | text `text-sm`, secondary columns muted, numbers right-aligned, dates in one format, truncate with tooltip for long text |
| Actions column | icon buttons right-aligned, `aria-label` + Tooltip, visible on row hover/focus but always visible on touch               |
| States         | loading (skeleton), empty (icon/Mascot + one sentence + one action), error (message + Retry), filled                     |
| Pagination     | infinite scroll with the end marker (as P-32), never "Load more"                                                         |

The MCP tools tab keeps cards (it is a catalog, not tabular data); only the Tokens tab table is migrated.

## C. Notification item (inbox and popover)

Files: `apps/web/src/client/modules/notification/components/notification-item.tsx`, `notification-list.tsx`, `notification-inbox.tsx`, `notification-inbox-bulk-bar.tsx`, `notification-popover-panel.tsx`, `consts/texts.const.ts`.

Problems today: a checkbox that fades in on hover and sits among the other controls; and per item **two** icon buttons (a check/mail toggle for read/unread and an archive icon) next to an unread dot, so it is not clear what each does.

Target:

- **The whole row is one click target**: click opens the object and marks it read (already done by `handleRowClick`). The unread state is only the left dot/tint.
- **One overflow menu** (`DropdownMenu`, trigger an icon button `MoreHorizontalIcon` with `aria-label` "Notification actions" and a Tooltip) at the end of the row, visible on hover/focus and always on touch. Items with text labels: "Mark as read" / "Mark as unread" (one of them, by state), "Archive". No two inline icon buttons.
- **Selection:** remove the per-row checkbox from the default state. Bulk actions live in the inbox page toolbar: a "Select" toggle enters selection mode, where every row shows a `Checkbox` in a fixed-width leading column (design-system `Checkbox` at the default size, vertically aligned to the first text line, no hover fade), clicking a row toggles selection instead of navigating, and the bulk bar shows "N selected · Mark read · Archive · Cancel". Outside selection mode there are no checkboxes. The popover never has selection.
- Keep the top-right "Mark all as read" in the inbox header.
- Row layout stays: avatar with type icon, message, project · time line. Add nothing new.
- Keyboard: Up/Down moves focus between rows (existing `onFocus` active ring stays), Enter opens, `Shift+F10`/context key opens the menu, Esc leaves selection mode.
- Texts EN+RU, remove the unused ones (`select`, `markRead` icon labels if unused).
