# P-47 Notifications: preferences and email (part 3 of 3)

Depends on P-45, P-46 and the tab layout from P-37/P-44. Adds the **Notifications** tab to Settings and optional email delivery (Resend is already used for invitations).

## Settings → Notifications tab

Uses `SettingsSection` (P-37). A matrix, one row per notification type group, two channel switches:

| Row (title + one-line description) | In-app | Email |
| --- | --- | --- |
| Assigned to me | on | on |
| New tickets in my projects | on | off |
| Status changes on my tickets | on | off |
| Comments on tickets I follow | on | on |
| Project access and role changes | on | on |
| Team: invitation accepted | on | off |
| Project archived or restored | on | off |
| Security: API key rotated, new token created | on (locked) | on (locked) |

- Layout: table-like rows, switches right-aligned in two labeled columns "In-app" and "Email" with sticky column headers; saves on change with a quiet "Saved" check (no Save button). Locked rows show a lock icon and tooltip "Always on for your security".
- Admin-only rows (for example "Team: invitation accepted", "API key rotated") are hidden for members.
- Header controls: **Pause all in-app notifications** switch is not included; instead a `Mute project` multi-select: "Mute notifications from selected projects" (applies to ticket types).
- **Email digest** section: select "Send emails: Immediately · Hourly digest · Daily digest (09:00 in my time zone)". Digest groups items by project in one mail.

## Behavior

- Preferences are stored per user (and per organization for muted projects), defaults as in the table.
- The notification producer (P-45) consults preferences at creation: in-app off means no row; email off means no mail. Security rows ignore preferences.
- Email: one template (existing email styling): subject "Anna assigned you SB-42", body with the sentence, project, a **View ticket** button; footer link "Manage notification settings" to this tab. Digest template lists items. Email language follows the user's interface language. Works without Resend configured (logs and skips, like the invitation mail).
- Emails are sent after the transaction commits, from a small queue-less deferred call; failure never affects the original action.
- Unsubscribe link in the footer opens the settings tab (no one-click token in v1).

## Tests

Use-case tests: preference filtering per channel, locked security rows, muted project, digest grouping, member does not get admin-only rows. Email template renders both languages.

## Out of scope

Slack/Telegram channels, mobile push, per-ticket follow/unfollow (v1 follows by assignee and participation).
