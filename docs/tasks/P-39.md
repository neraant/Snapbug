# P-39 Playground: clear purpose and layout

Page: `apps/web/src/app/(app)/playground/page.tsx`; module `client/modules/playground` (`playground.tsx`, `playground-sample.tsx`, `playground-capture.tsx`, `playground-environment.tsx`, `playground-replay.tsx`). Keeps P-17 and P-29 rules: nothing is written to the database or Blob; capture uses the ticket-card layout.

## Problem

It is not obvious what the page is for, what to click, and where the result appears. The two surfaces compete for attention and the layout feels accidental.

## Result

A guided two-step page, like a "try it" screen in Sentry/PostHog onboarding.

### Header

Title "Playground", description "Try the widget on a sample page. Nothing you submit is saved." plus a muted `Badge` "Sandbox — no data is saved".

### Step strip (under the header)

Three inline numbered steps: **1 Interact with the page** · **2 Report a bug** (`Alt+S` shown as a keycap, or click the widget button) · **3 Review the capture**. The current step is highlighted; it advances automatically (step 3 after submit). Compact, one line, not a tutorial.

### Layout

- Two panes side by side at ≥1280 px (sample 60 % / result 40 %), stacked below that (sample first, result below).
- **Left: sample** inside a browser-frame mock (rounded border, fake address bar `shop.example.com/checkout`, three window dots) so it reads as "a customer's site". The checkout content stays (P-29). The real widget button sits at the bottom-right corner **inside the frame**, not the page.
- **Right: result panel** (a `Panel`/`Card` titled "Captured report").
  - Before submit: empty state with an arrow/illustration, "Submit a report from the sample page to see what we capture" and a button "Open the widget" that opens it.
  - After submit: the ticket-card layout from P-29 (title and description, screenshot, replay, diagnostics, environment), as tabs inside the panel — **Overview · Screenshot · Replay · Console · Network · Environment** — rather than one long scroll. Panel header actions: `Reset` (clears the capture and returns to step 1) and nothing that implies persistence.
- Pending submit shows a spinner skeleton in the result panel. Errors show inline in the panel with Retry.

### Details

- Add a "Make something go wrong" mini helper on the sample: a "Pay now" button that throws a console error and fires a failing network request, so the Console and Network tabs have content. Label it plainly (muted caption "Triggers a sample error").
- Result panel is sticky while the left pane scrolls.
- All strings in `texts.const.ts` (EN + RU).

## Out of scope

Writing data, tickets from the playground, new SDK features.
